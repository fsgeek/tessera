## Runner bugs and exact fixes

1. **HIGH — Manifest counting semantics can change without audit rejection.** `R:35-41,99-107,127-133,382`; `M` is authoritative for kind, id, condition and expected polarity, but its registered SHA256 is merely printed at `R:393`, never compared. Removing T/H/L from manifest conditions similarly permits suppressing necessary fallbacks.

   **Exact fix:** pin manifest SHA256 `80cdfbd728dc5162eec567cf57c0ba89ccbfe3240bf5ef7e336e2830a4a0f6ba` and fail before parsing on mismatch. Parse the verified bytes once and return those rows from the audit; remove the second unverified read at `R:382`. Recheck that pin during batch provenance checks. Retain count/file checks. Pin the refreshed runner externally in the freezing record and update `S:315` after repairs.

2. **HIGH — A post-audit provenance change can escape detection and yield counted results.** `R:121-125,156-160,293-312,377,400-425`. Only the run's model blob is checked after execution. The library, ProVerif binary, derivation tools, manifest and source files can change after the single startup audit, including during hours of controls, while every logged `provenance=OK` still refers only to the unchanged model. A model changed before launch is nevertheless executed before its mismatch is discovered. This violates `S:310-311` and the stop promise; a library change between controls and primaries makes the closed gate irrelevant to the actual primary semantics.

   **Exact fix:** retain a complete frozen provenance map from the audit. Immediately before each launch (after memory acquisition), compare that model's blob plus all shared tool/library/manifest pins and source blobs; on mismatch, do not launch, mark the batch stopped and withhold all results. Repeat these checks after each run and before closing the control gate and declaring batch completion. Use one shared stop state for these failures. Preserve the checks' actual hashes in the log. These boundary checks detect persistent changes; if protection against change-and-restore during a subprocess is intended, execute verified immutable snapshots or add monitoring rather than claiming boundary hashes detect every transient edit.

3. **MEDIUM — Waiting workers can start after the batch has detected a red or provenance mismatch.** `R:299-301,336-344,400,412,418`. `work()` checks stop before `run_one()` acquires its memory budget. With `--jobs` greater than the concurrent memory capacity, workers can wait inside `Budget.acquire`; after another worker detects a stop, they can acquire released memory and launch without another stop check. A narrow check-to-launch race also exists for nonwaiting workers. Already running controls finish before phase-1 adjudication, so this does not bypass the phase barrier; queued primary/fallback runs can nevertheless launch after a provenance stop.

   **Exact fix:** pass the shared stop state to budget acquisition and run launch. Wake waiters on stop, release reserved memory when cancelling, and serialize stop-setting with the final stop check and subprocess creation under a launch lock. Define subprocesses already launched at detection as in flight; prohibit any new launches afterward. Validate positive `--jobs` at argument parsing. Alternatively use a supervisor that dispatches only memory-admissible work and stops dispatch immediately on failure.

4. **MEDIUM — Independent set scan ignores leading whitespace.** `R:114-115`. `^set .*` misses an additional `  set maxDepth = 1.`. The copied-library test updates only that library's pin in the copied runner to exercise the construct scan independently; audit passes on the indented directive. The equivalent unindented directive fails. With original pins, either library mutation fails at the pin check; this test exposes the promised independent scanner's gap, not a bypass of an intact library pin. Slice mutations also fail earlier at exact regeneration.

   **Exact fix:** on comment-stripped text find all `set` directives with a whitespace-insensitive token boundary, e.g. `re.findall(r'\bset\s+[^.]*\.', clean)`, then normalize whitespace and compare the entire ordered directive list against the permitted list (empty for the library, exactly `set selFun = Term.` for model files). Reject any extra directive regardless of indentation or position.

5. **MEDIUM — A8.4 safety tags ignore unsuccessful execution.** `R:347-355,424-425`. rc is applied to the witness tag but not to C-Q6k. A synthetic rc=124 output containing a completed safety true and a witness result produces `C-Q6k=true A8.4w=INCONCLUSIVE`. The same issue permits `C-Q6k=false+trace` after nonzero rc. These are misleading countable-looking tags even though the registration rejects rc≠0; provenance is likewise absent from the tag and checked only after logging it.

   **Exact fix:** first reject `not x['prov']` or `x['rc'] != 0` in `a84_tags` for both queries; return explicit uncountable statuses and retain any raw partial RESULTs only as diagnostics. Require exactly the two expected query results. For a safety false without its own trace, tag it `NOT_SHOWN`, not a reconstructed red. For a safety true, explicitly tag non-vacuous green as eligible only when the separate witness is reachable with its own trace; otherwise tag green withheld/non-vacuity unshown. Check provenance before logging semantic tags.

6. **LOW — Existing empty log is accepted; startup refusal is not atomic.** `R:386-391,290-291`. The documented promise refuses an existing `counted.log`; implementation refuses only a nonempty one. Two processes can also both pass the log/out checks before either writes, then interleave batch logs and contend on output files. Exclusive creation of individual `.out` files does not lock the batch.

   **Exact fix:** acquire a batch lock atomically before testing/creating artifacts; reject any existing `counted.log`, including zero bytes, and any nonempty output directory. Create the batch log exclusively with mode `x` while holding that lock, and retain exclusive batch ownership through completion. Refuse concurrent invocations cleanly. 7. **MEDIUM — Timeout has no forced-kill deadline.** `R:297-301`. The memory reservation logic caps summed MemoryMax at 24 GB and A8.4 runs sequentially at 16 GB; the stated per-run values match the registration. However, `timeout N` sends TERM at N and can wait indefinitely if the child does not terminate. Thus the supervisor does not enforce an unconditional wall-time ceiling or release its budget reliably at that deadline. This is a source-path assessment; no actual ProVerif termination behavior was tested.

   **Exact fix:** add an explicit bounded kill grace, e.g. `timeout --kill-after=10s N ...`, and document the grace in the registration. Ensure timeout controls remain inconclusive for any nonzero exit and kill the run's remaining subprocesses before returning its memory reservation. This retains the registered work interval while bounding cleanup.
