# Key ceremony rehearsal 1 — repository root, throwaway key (2026-11-01/02)

Performed by the author on a Tails live session, network off; directed by the owner. Purpose: learn whether a
P-256 key generated on Tails and used from a YubiKey produces signatures the V1 verifier accepts on the git path,
and time the steps, before the real ceremony (YubiKey A, repository root; YubiKey B, release key).
Procedure basis: `docs/V1-RELEASE-KEY-CUSTODY-DRAFT.md` §6–§8; key type from `docs/V1-PROFILE.md` §15.4.

## Hardware
- YubiKey C (spare; rehearsal only), serial 39975816. Reader `1050:0407` (YubiKey 5, OTP+FIDO+CCID); OpenPGP
  application 3.4 (firmware ≥ 5.2.3, so P-256 capable). Factory state on arrival: no keys, PIN retries 3/0/3,
  signature counter 0, KDF off, UIF off, key attributes rsa2048 ×3. (Photo: author, public fields only.)

## Throwaway key
- `6F3D071A8761DF5187C578DABB89158A63C8EA8F`, nistp256 (algo 19), created 2026-11-02 (epoch 1793577872),
  uid "Tessera repository root REHEARSAL <tessera@wamason.com>", capabilities scSC. Discarded with the session.

## Result (owner, on the NUC, from the transfer stick mounted read-only, noexec)
- GnuPG (isolated keyring): good signature. Packet: v4, sigclass 0x00, digest SHA-256 (8), hashed {33 issuer fpr,
  2 creation time}, unhashed {16 issuer key id} — the layout profile §8 expects.
- Verifier code (`tessera_verify.git_channel.dearmor`, `codec.sig_policy`, `codec.public_key(·, 'gpg')`,
  `codec.signature_verifies`): armor, rule O and policy PASS; the 82-byte v4 key body accepted; signature over
  `t.txt` verifies; one byte changed: does not verify.

## Lessons for the real procedure
- Add `key-attr` (signature slot → ECC, NIST P-256) before `keytocard`; factory slots are RSA 2048.
- The exported public key starts with an old-format packet header with a one-byte length (`0x98`).
- The author declined to photograph the secret key even in rehearsal: keep that rule explicit for the real one.
- The transfer stick touched the NUC; it is "out only" from now on and never returns to a signing session.
- Author's notes: `forcesig` and `uif 1 permanent` both returned silently (accepted). Signing asked for the
  **user** PIN. The first attempt failed with a **timeout**: GnuPG does not say "touch the key", the YubiKey only
  blinks. The second attempt, with a touch, succeeded. So touch is enforced; the procedure must say "when the
  YubiKey blinks, touch it within about 15 seconds". Each step took a few seconds.
- YubiKey C: factory reset (step 8) still pending as of 2026-11-02; to be done before the session shuts down.
- The author on not photographing the secret key: "the walk-through is when I want to instill the discipline,
  so I don't screw it up when the real thing is ready." The rehearsal is practice of the habits, not only a test of
  the tools.
