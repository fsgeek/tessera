# Dispositions of the Codex review of the watcher (2026-11-22)

Review: `docs/reviews/watcher/CODEX-REVIEW.md` (brief `BRIEF.md`). Dispositions set by the steward; implemented on
branch `watcher-fixes`. FIXED = changed in code or Terraform (with a test); NARROWED = the claim in
`service/watcher/README.md` or `docs/V1-DETECTION-CONTRACT.md` now says only what holds; ACCEPTED = left as is, with
the reason. Owner's unit tests over fakes only; nothing here has been seen to fire on a deployment.

| Finding | Disposition | What changed |
|---|---|---|
| H1 missing receipt aborts the run | FIXED | Role gains unconditional `s3:ListBucket` on the results bucket (absent object = 404 = `RECEIPT_OBJECT_MISSING`). Any other read failure is D8 `RECEIPT_OBJECT_UNREADABLE` (class name), retried to the 6 h bound. Every trail file, trail record, `SIGLOG#` entry, request, receipt check and trace write is isolated: a failure is a `W` finding (`ITEM_CHECK_FAILED`, `TRAIL_FILE_UNREADABLE`, `TRACE_WRITE_FAILED`; id or rid prefix, class name) and the run goes on, publishes, commits and heartbeats. Only a failure of the run as a whole (state load/commit) skips the heartbeat via the handler's `WATCHER_ERROR`. Also withholding the heartbeat (owner's choice, stated): a whole source unreadable (`SOURCE_UNAVAILABLE`), a finding not published, a failing verifier self-check: the watcher is then partly blind or mute, so D9 should fire if it persists. |
| H2 issuer inputs control cursors and suppression | FIXED + NARROWED | No issuer-time watermark remains: issuer items are new while their key is not in the seen set, which forgets a key only when the item leaves the (complete, consistent) scan. The trail cursor moves by the watcher's clock minus 1 h only. An issuer time > 5 min ahead is `ISSUER_TIME_IN_FUTURE` and never counts for D6. README and contract (b) now say: resource separation, not integrity of issuer-controlled observations; a principal able to write the issuer table can suppress D5/D8 for rows it deletes or alters; CloudTrail is the independent evidence (a deleted `SIGLOG#`/COMPLETE still surfaces as an unmatched `kms:Sign` under D6). State and trace buckets now refuse writes by any principal but the watcher role. |
| H3 unverified or unshipped signatures satisfy D6 | FIXED + NARROWED | D6 counts only signatures with a `SIGLOG#` `used` entry, or recorded on a kms job (the issuer's equivalent). `duplicate`, `not-waiting`, `other-attempt` and D5 dispositions never count. A used signature of an attempt that did not ship counts and is shown in the trace record (`attempts[].state`), not alarmed. A job signature never logged is D6 `JOB_SIGNATURE_NOT_LOGGED`. Contract D6 row, item (b)2 and Status now say "kms:Sign events against signatures the issuer verified and used, by time and count". |
| H4 secrecy boundary | FIXED | New `tessera_watch/sanitize.py`: every field of every finding, log line, SNS message, trace record and stored sig/sign entry passes a per-field rule (codes `^[A-Z0-9_]{1,64}$`, hex of exact length, enums, rid as 16-hex prefix outside the trace, RFC 3339, UUID, ARN shape) or is `<withheld>`; a field without a rule is withheld; compound reasons are split into two codes; outbox entries are validated again on the way out. Exceptions are reported by class name only. The handler catches `BaseException`, logs and publishes `WATCHER_ERROR` with the class name, and returns. `tests/test_secrets.py` (222 cases) injects a URL, a request key, content, an API key value and exception text into every SIGLOG#, REQ# (record, attempt, end, job, job name, item key) and CloudTrail field, SDK and verifier exceptions, and the outbox, and asserts none reaches the log, SNS, trace, outbox or state. Residual: CloudTrail-written fields (`eventName`, `eventID`, role ARNs) are checked by shape; a value of that shape (e.g. a role named like a key) passes. |
| M1 late CloudTrail delivery | FIXED + NARROWED | Matching is recomputed each run over everything not final; a signature's match is final 47 min after it was logged, a Sign is declared unmatched 45 min after its time; trace records wait for finality. Bootstrap: only signatures logged before coverage start are `before-coverage` (one logged after it with no Sign alarms; README states the possible bootstrap false alarm). A Sign later than the 45 min delivery bound can be reported (stated). |
| M2 windows discard unseen evidence | FIXED | The first run creates its state (coverage start) before reading anything. The trail cursor never passes an unread file (held back to it; abandoned with `TRAIL_FILE_ABANDONED` after 24 h) and moves only by the watcher's clock, so an outage loses no file. Issuer items have no time floor (see H2). Stated residual: a file appearing more than 1 h after its key time once the cursor has passed it. |
| M3 durable delivery of findings | FIXED + NARROWED | Each finding is written to the outbox (`findings/<digest>.json`, state bucket) when found, before any trace write; each is deleted only after SNS accepts it; failed publications do not stop the others and are retried next run (heartbeat withheld meanwhile). README and contract say delivery is to the topic; email needs the confirmed subscription. |
| M4 D8 can run out of time | FIXED | One deadline per check (invocation time left less 90 s, at most 360 s) shared by explorer requests and the verifier process; > 32 heights is `RECEIPT_UNCHECKED` at once with no explorer calls; heights must be integers in range (infinity, floats, booleans go to the verifier, never raise); at most 10 checks a run, least recently tried first; a receipt deferred behind a backlog for 6 h is `RECEIPT_UNCHECKED` (`D8_BACKLOG`); an unexpected check failure is bounded the same way. |
| M5 zero or incomplete trace records | FIXED | A pending request keeps a validated snapshot; if its `REQ#` expires, the trace is written from it (`record_source: snapshot`, `TRACE_FROM_SNAPSHOT`). A kms job signature not yet in `SIGLOG#` holds the trace (up to 30 min, then `not-logged` and D6 `JOB_SIGNATURE_NOT_LOGGED`). A missing/invalid terminal time is `TERMINAL_TIME_INVALID`, and the trace is still written. A failed trace write is retried every run until written. |
| M6 Object Lock and moving retention | FIXED + NARROWED | Retention is a constant 400 days in Terraform (`local.trace_retention_days`) and in code (`lambda_app.TRACE_RETENTION_DAYS`, applied to the `window.json` packaged in the zip); both deploy variables and `TRACE_RETAIN_UNTIL` are removed. Default retention COMPLIANCE 400 days; versioning on. Bucket policy adds: deny put without lock mode or without retain-until (`Null`), deny put by any principal but the watcher role, and deny to every principal `DeleteObject` (no delete markers), `DeleteObjectVersion`, `PutBucketObjectLockConfiguration`. The role loses `s3:PutObjectRetention`. State bucket: writes and deletes only by the watcher role. README states the residual: an account administrator can rewrite the bucket policy first (a D7 event); the locked versions survive. |
| M7 heartbeat bound | FIXED + NARROWED | The alarm is now a metric-math `FILL(hb, 0)` over 600 s periods, 3 of 3, so it does not rely on the missing-data look-back: it fires 30 to 40 min after the last heartbeat plus CloudWatch evaluation (platform). README, contract D9 row and the Terraform comment say it measures sustained silence; intermittent failures are the Errors alarm's (timeouts and runtime faults only, since the handler never raises). |
| M8 packaging determinism and install check | FIXED | Wheels from `service/watcher/requirements-lambda.txt` (cffi, cryptography, pycparser, every artifact hash-pinned), installed `--require-hashes --no-deps`; the whole frozen objects tree is staged, as the issuer's. Tests: lock contents and install command; a full build twice (resolved wheels included) gives the same SHA-256; the install-record check refuses each wrong field. A record from another runtime cannot be seen at build time, so every run performs the verifier's own startup check (`lambda_app.selfcheck`) and reports `VERIFIER_SELF_CHECK_FAILED` and withholds the heartbeat. README deploy step now reads the runtime ARN from the bootstrap function, as `service/issuer/DEPLOY.md` step 3. |
| M9 a valid receipt traced to the wrong request | FIXED | After `VALID_STRICT`, `receipts.binding` reads (with the frozen codec) the attested content's SHA-256 and length, the four signatures' SHA-256, A_sig's SHA-256 and the declared issue time; they must equal the record's content, the shipped attempt's jobs, `receipt_id` and `declared_issue_time`. Otherwise D8 `RECEIPT_NOT_THIS_REQUEST` (fields named) or `RECEIPT_NOT_BOUND`, and the trace says `NOT_BOUND` with no anchors or T. The trace is keyed and bound by the validated 64-hex rid and `receipt_sha256`. |
| L1 conflated detection paths | NARROWED | README D5 row: only `SIGLOG#`; KMS `KeyMismatch` is the Errors alarm's; signer-only refusals and GCP `refuse_to_run` are outside the watcher. Contract D5 row likewise. D6 `AccessDenied` qualified to the issuing account's trail. Contract D7 latency column now says IAM via the watcher is up to ~1 h. README: D1-D4 "not built yet". |
