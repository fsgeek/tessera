# Codex review of the detection tests

## Safety and cleanup

1. **HIGH — D3b writes to the production request table on its normal 413 path.** Each call supplies a fresh valid request UUID and 1,100,000 bytes. The issuer constructs a terminal `REFUSED/TOO_LARGE` record and atomically creates it with its tombstone before returning 413. Six successful stimuli can leave six records and six tombstones. The refusal guard prevents issuance on this path, but it does not prevent the production write. Mark the issuer-level D3b path NOT COVERED under the current boundary and remove it from live dispatch. The D3a non-UUID branch returns before this write. [api_tests.py:293](../../../service/detect/tests-live/api_tests.py#L293), [api.py:115](../../../service/issuer/tessera_issue/api.py#L115), [api.py:134](../../../service/issuer/tessera_issue/api.py#L134), [aws.py:72](../../../service/issuer/tessera_issue/aws.py#L72), [brief:17](BRIEF-gemini.md#L17).

2. **HIGH — Recovery trusts an unattested name-to-identifier mapping.** A stale, mistaken or edited ledger can pair a test-looking display name with a live production KMS key reference, API Gateway resource ID or subscription ARN. Recovery schedules the key for deletion, deletes the API, key or usage plan, or unsubscribes the existing author subscription using that identifier directly. The live membership checks do not protect these branches. Named resources also lack account, run and ownership checks. Recovery must verify the actual target and its run ownership, including the exact topic, protocol and owned SQS endpoint for any subscription, before mutation. [d7_tests.py:1050](../../../service/detect/tests-live/d7_tests.py#L1050), [d7_tests.py:1081](../../../service/detect/tests-live/d7_tests.py#L1081), [d7_tests.py:1119](../../../service/detect/tests-live/d7_tests.py#L1119).

3. **HIGH — The HTTP guard validates the input path while the transport controls the actual destination.** An HTTPS URL for another host or region passes configuration checks and receives the smoke key. Default redirect handling can forward the key on a redirected GET, including a GET resulting from a redirected POST, outside the approved origin and path without pacing or quota accounting. A wrong endpoint can also implement acceptance semantics different from the reviewed issuer. Bind the configured base to the approved API Gateway origin and stage, reject redirects, and use the reviewed refusal conditions on the effective request. A 2xx check after reading the response body cannot undo a side effect and a read failure can bypass that check. [api_tests.py:40](../../../service/detect/tests-live/api_tests.py#L40), [api_tests.py:74](../../../service/detect/tests-live/api_tests.py#L74), [api_tests.py:103](../../../service/detect/tests-live/api_tests.py#L103).

4. **HIGH — Region configuration does not bind AWS destinations.** The client factory checks two environment fields and passes a region name. SDK endpoint overrides can still route calls elsewhere. SQS URL validation searches for a region substring anywhere in the string, and S3 bucket names carry no region or account binding. For example, an existing bucket adopted by name can be addressed by S3 in its actual region. IAM writes use the global service regardless of the client region and touch account-wide state. That affects default Lambda and IAM-role tests, the access-key opt-in, and their recovery. Enforce the effective regional endpoint and account, and resolve the global IAM scope explicitly under the brief before permitting those calls. [safety.py:119](../../../service/detect/tests-live/safety.py#L119), [safety.py:316](../../../service/detect/tests-live/safety.py#L316), [d7_tests.py:214](../../../service/detect/tests-live/d7_tests.py#L214), [d7_tests.py:490](../../../service/detect/tests-live/d7_tests.py#L490), [d7_tests.py:604](../../../service/detect/tests-live/d7_tests.py#L604), [AWS IAM endpoints](https://docs.aws.amazon.com/general/latest/gr/iam-service.html), [Botocore endpoint configuration](https://docs.aws.amazon.com/botocore/latest/reference/config.html).

5. **HIGH — A test prefix and create response do not establish exclusive ownership.** Reusing a run ID after an interrupted or concurrent run can adopt an existing queue/topic or overwrite an existing alarm or rule. The observer can then overwrite the queue policy, consume/delete messages, adopt a subscription returned for the same endpoint and unsubscribe it. S3 cleanup can empty a reused bucket. Require a fresh run and verify exclusive ownership before changing or deleting resources. Existing guards cover many generated names and response IDs, but observer receive/delete rely on the earlier URL check, supplementary SQS changes attributes before checking its returned URL, and API Gateway attachment relies on earlier ID checks. A target invariant must hold for every mutation, including dependent calls and recovery. [run_tests.py:148](../../../service/detect/tests-live/run_tests.py#L148), [observer.py:78](../../../service/detect/tests-live/observer.py#L78), [observer.py:122](../../../service/detect/tests-live/observer.py#L122), [observer.py:177](../../../service/detect/tests-live/observer.py#L177), [d7_tests.py:319](../../../service/detect/tests-live/d7_tests.py#L319), [d7_tests.py:426](../../../service/detect/tests-live/d7_tests.py#L426), [d7_tests.py:844](../../../service/detect/tests-live/d7_tests.py#L844), [d7_tests.py:861](../../../service/detect/tests-live/d7_tests.py#L861), [d7_tests.py:938](../../../service/detect/tests-live/d7_tests.py#L938), [d7_tests.py:1013](../../../service/detect/tests-live/d7_tests.py#L1013).

6. **HIGH — Recovery does not cover the AWS commit-to-local-record gap.** A killed process, lost response or retry after a committed create can leave an untracked KMS key, subscription, API Gateway resource or any other create. The observer widens the queue gap with a separate attribute lookup before journaling. Grants, the usage-plan attachment, inline role policy, Lambda permission and the IAM access key have no individual cleanup ledger entry. Some are removed with the parent, but a grant can linger on a scheduled key and a key can block IAM user deletion. Record durable intent and reconcile ambiguous creates and dependent resources using verified ownership. Reusing a run ID currently replaces the previous ledger. A disk failure during one cleanup handler can also prevent later cleanup. [ledger.py:31](../../../service/detect/tests-live/ledger.py#L31), [ledger.py:47](../../../service/detect/tests-live/ledger.py#L47), [d7_tests.py:80](../../../service/detect/tests-live/d7_tests.py#L80), [d7_tests.py:135](../../../service/detect/tests-live/d7_tests.py#L135), [d7_tests.py:179](../../../service/detect/tests-live/d7_tests.py#L179), [d7_tests.py:426](../../../service/detect/tests-live/d7_tests.py#L426), [d7_tests.py:550](../../../service/detect/tests-live/d7_tests.py#L550), [d7_tests.py:620](../../../service/detect/tests-live/d7_tests.py#L620), [d7_tests.py:678](../../../service/detect/tests-live/d7_tests.py#L678), [observer.py:88](../../../service/detect/tests-live/observer.py#L88), [observer.py:135](../../../service/detect/tests-live/observer.py#L135).

7. **MEDIUM — Recovery can report process success with residual resources.** Recovery prints failures but returns zero and never persists the results. A lost schedule-deletion response leaves an active ledger entry even if KMS already scheduled deletion. A failed cleanup of an active IAM key can leave both the key and user, and the next recovery trusts the same stale ledger. S3 bulk deletion ignores per-object failures and does not remove versions or delete markers. A crash during observer teardown leaves any unfinished work to this same recovery path. Combining `--dry-run` and `--cleanup-ledger` runs destructive cleanup because its branch executes first. Reject incompatible flags, record verified results durably and fail the command when resources remain. [run_tests.py:137](../../../service/detect/tests-live/run_tests.py#L137), [run_tests.py:230](../../../service/detect/tests-live/run_tests.py#L230), [d7_tests.py:844](../../../service/detect/tests-live/d7_tests.py#L844), [d7_tests.py:1081](../../../service/detect/tests-live/d7_tests.py#L1081), [d7_tests.py:1128](../../../service/detect/tests-live/d7_tests.py#L1128).

8. **MEDIUM — Pacing and quota limits apply to fragments of traffic.** Each row starts a new limiter with an immediate first request. A fast D2a/D2b boundary can emit two adjacent starts without the advertised burst-one spacing. Three concurrent API runners at 2 rps can sustain 6 rps, and redirects and repeated invocations also sit outside the shared pace and daily count. The default limit of 60 attempts can still exhaust an already-used key. Use a single pacer for the run, block wire retries that bypass it, and account for other use when deciding whether a live run can proceed. [safety.py:246](../../../service/detect/tests-live/safety.py#L246), [api_tests.py:122](../../../service/detect/tests-live/api_tests.py#L122), [api_tests.py:174](../../../service/detect/tests-live/api_tests.py#L174), [run_tests.py:170](../../../service/detect/tests-live/run_tests.py#L170).

9. **MEDIUM — Output contains URLs and can contain secrets.** A normal observer run records the full SQS URL as the queue identifier and prints it in the cleanup summary. Raw exceptions and cleanup summaries bypass redaction, including failures before ledger creation. Only configured API strings and certain AWS ID shapes are scrubbed in string values. Raw SNS excerpts, stringified errors and dict keys remain channels for unknown or transformed secrets, for example a notification containing a URL or a transport error containing a configured endpoint. Use structured allowlisted evidence and redact every output path. Recover queues by verified non-URL identity. ## Opt-ins

10. **MEDIUM — Quota opt-in can impair the smoke lane even if D4c fails.** It raises the whole process cap from 60 to 120, then sends one status GET every eight seconds until any 429 or the cap. Default ordering leaves up to 65 D4c calls after D4a reaches 55. A D4c-only run can send all 120. A timeout or abort after exhausting the shared key leaves that day's quota consumed. `--only` can reorder or duplicate cases. Duplicate opt-in tests can survive filtering even with their flags absent because each `remove` removes only one instance. Enforce opt-ins on final dispatch and enforce D4c last. Require the exact logged quota error for a pass. [run_tests.py:98](../../../service/detect/tests-live/run_tests.py#L98), [run_tests.py:170](../../../service/detect/tests-live/run_tests.py#L170), [api_tests.py:386](../../../service/detect/tests-live/api_tests.py#L386), [api_tests.py:420](../../../service/detect/tests-live/api_tests.py#L420).

11. **MEDIUM — CloudTrail opt-in tests a StopLogging call on a trail that was never started.** It creates and tags a bucket, adds a policy authorizing the named trail, creates a single-region trail, enables validation, selects read-only management events, calls StopLogging, and deletes the trail and bucket. A StopLogging notification can show detection of the call, with no evidence that an active trail stopped. Request or cleanup failure can strand the trail and bucket/policy, consume a trail slot and leave later rows unexecuted. The scripted sequence does not initiate log delivery. Scope the result to the observed call and verify its success or error from CloudTrail. [d7_tests.py:708](../../../service/detect/tests-live/d7_tests.py#L708), [d7_tests.py:770](../../../service/detect/tests-live/d7_tests.py#L770), [PLAN.md:104](PLAN.md#L104), [AWS trail setup](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-create-and-update-a-trail-by-using-the-aws-cli-create-trail.html).

12. **MEDIUM — IAM opt-in creates an active global credential with no independent durable reconciliation record.** It creates a tagged user with no attached policy, creates the key, clears the returned material in memory, then tries to delete the key and user. If the key creation commits and its reply is lost, the ordinary finally has no key ID and user deletion can fail. The surviving user and active key remain until verified recovery enumerates and removes the credential. The lack of an attached policy limits direct permissions but does not make the identity inert for policies that grant it access. Capture cleanup by user identity and enumerate keys before completing cleanup without journaling credential material. ## Plan fidelity and observed evidence

13. **HIGH — A completed run can have no correlated detection or mailbox evidence.** The runner discards row return values, counts all SNS messages, dumps unjoined alarm history, and only reminds the operator about email. The manual steward read is the correct access boundary, but there is no evidence handoff that associates the mailbox arrival and exact alarm/event IDs with each action and endpoint deadline. For example, a pre-existing unrelated alarm notification can increase the count while D2 never fires. Persist a row-specific result with positive evidence for each observed endpoint and an explicit open result where evidence is missing. An exit code of zero proves only completion of the scripted operations. 14. **HIGH — Default timing can miss successful SNS delivery outright.** The observer polls only after all tests, for 180 seconds by default. A short IAM run can destroy its queue before the watcher publishes within its allowed hour. A short API run can finish before evaluation, and the D4 volume alarm has a daily period. Unsubscribe is issued after the last poll and the queue is immediately deleted, so its own SQS evidence is especially unreliable. For the unsubscribe row the steward's email or a separately authorized observation method must be made explicit. Keep the observer alive for the relevant window and distinguish enqueue time, receive time and mailbox arrival.
