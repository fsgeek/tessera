# Operator-sheet findings — 2026-11-06

Line numbers refer to `docs/ceremony/OPERATOR-SHEET.md` (SHA-256 `0fa7d137651e500867f7e3ef03eb78376a43671557dbd64ef49dc5d1c6f241e7`). Document and GnuPG 2.4 source review; no Tails/card rehearsal performed.

- **HIGH — lines 17, 36–37, 77, 89, 152–153: the blanket shutdown/restart rule is unsafe and contradicts the recovery instructions.** If step 6's export or restore fails while the new key exists only in RAM, line 17 discards that working copy instead of repairing the backup in the same session as line 77 requires. If the backup becomes unreadable after `keytocard`, a later Part 1 error followed by shutdown and rehearsal C's reset destroys the remaining working card copy. For A/B, restarting instead reaches step 2's “no keys” stop; it does not reset the card as line 17 promises. Replace the blanket rule with phase-specific recovery: before a proven backup, retain the live keyring and repair the backup; after transfer, preserve the card and backup and seek an owner decision. Explicitly state which instruction wins when errors occur.

- **MEDIUM — lines 37, 100–105: unconditional `forcesig` can turn the required policy off.** An empty A/B card with retries `3 0 3` can already have forced signature PIN enabled; step 2 does not constrain that setting. Running `forcesig` once then disables it, and step 9 stops after key transfer. Read the setting first and toggle only when it is `not forced`, then retain the existing readback requirement. GnuPG implements this command as a [toggle of the current CHV status](https://github.com/gpg/gnupg/blob/gnupg-2.4.7/g10/card-util.c#L1205-L1224).

- **MEDIUM — lines 114–116, 152: `NO-SIGNATURE-OK` does not establish a touch timeout.** Canceling PIN entry, entering a wrong PIN, or losing the card connection also leaves no signature and prints the accepted marker. Thus a positive test followed by a canceled negative test can satisfy the written conditions without testing refusal for lack of touch. Require the expected touch-timeout diagnostic and a nonzero signing exit status, after successful PIN entry with the card still present; treat other errors as inconclusive and rerun after recovery. Preserve the no-output-file check as an additional condition.
