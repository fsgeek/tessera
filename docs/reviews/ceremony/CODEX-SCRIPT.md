# Script findings — 2026-11-06

Lines refer to `docs/ceremony/tessera-ceremony.sh`. Static/source review and a synthetic GnuPG 2.4.4 key/signature check; no Tails/YubiKey rehearsal. The exact generation command passed the service verifier's `public_key`, `parse_signature`, `sig_policy` and `signature_verifies` checks, consistent with profile §15.4 and §8.

- **HIGH — 93–105, 123–127: retrying backup can destroy the proven export and certify a card stub instead.** After `tocard`, rerunning `backup` truncates `secret.asc` before exporting the now card-backed key. GnuPG can export a secret-key stub; importing it and signing while the card remains inserted can pass the “restore” test. The real export is gone and the card is the only usable copy. Even an export failure after truncation contradicts “Nothing was deleted” (15). Forbid backup after transfer, preserve the previous export until a replacement is independently proven, and test restoration with the card absent. Clear/re-establish `RESTORE_OK` when backup contents change.

- **HIGH — 41–44: the rehearsal reset advice can target this run's key.** Rerun `card` after rehearsal `tocard` (for example, while diagnosing a later failure): it instructs a factory reset without checking `FPR` or transfer state. If the backup has become unreadable, following that advice destroys the remaining usable key. Refuse reset advice whenever the card holds the current run's fingerprint; route that condition to preservation/recovery. The later “never reset” warning does not make these conflicting instructions safe.

- **MEDIUM — 55–56, 65–67, 134–144: interactive operations can fail yet print PASS.** Exit `passwd` without changing either default PIN, or let `gpg --card-edit` fail: `pins` still passes. The slot grep accepts `nistp256` in *any* of the three attributes, so RSA signature / P-256 authentication also passes. If the signature-PIN query fails, its absence is treated as “forced”; a succeeding UIF query can then produce policy PASS. Check command status and positive, field-specific readback; PIN changes require an explicit completion check rather than unconditional PASS.

- **MEDIUM — 28–33, 78, 97, 105, 116–118, 162: unchecked infrastructure failures undermine PASS and recovery.** A failed `ip` pipeline appears as zero UP links; a failed `save` still permits PASS (including after generation, leaving the recorded fingerprint empty); failed `sync` permits backup/public/test PASS and instructions to eject. A failed `sha256sum` still says the public key is written without yielding the required hash. Check these results explicitly. In particular, preserve and recover the generated fingerprint before permitting a retry to generate another key.

- **MEDIUM — 156–160: an English substring is not a touch-timeout discriminator.** The expected English diagnostic for the OpenPGP acknowledgement timeout is `gpg: signing failed: Timeout`: GnuPG 2.4.4 maps `SW_ACK_TIMEOUT` (`0x6600`) to `GPG_ERR_TIMEOUT` ([status definition](https://github.com/gpg/gnupg/blob/gnupg-2.4.4/scd/apdu.h#L34), [mapping](https://github.com/gpg/gnupg/blob/gnupg-2.4.4/scd/iso7816.c#L61)). But a pinentry timeout also matches `time`, allowing PASS without reaching touch, while localized diagnostics can reject a real touch timeout. Fix the diagnostic locale, distinguish PIN-entry failure from card acknowledgement timeout using status/agent evidence, and validate that distinction on the actual Tails/card combination; nonzero exit plus no signature alone is inconclusive.

- **MEDIUM — 169–186: “each work alone” is partly an operator assertion.** On the intended fresh keyring, the first test imports only public material, so it does use the card. However, the second test never checks that the card was removed. Leave it inserted and supply a stub-only backup: import and signing can both succeed using the card, producing the false backup PASS. Require card absence and actual local secret material for the restore test. Also check `mktemp`/permissions before any import: an empty failed temporary-home assignment loses the intended isolated-keyring guarantee.

- **LOW — 8, 30, 75, 99–104, 183: the secret-storage promise is literally false.** Generation and both restoration tests write secret key material into RAM keyrings outside `/media/amnesia/$L-PRIV`. This is expected by the ceremony, but an author reading “never writes a secret anywhere except” could reasonably infer otherwise. State the actual boundary: volatile RAM keyrings plus the encrypted backup volume; validate the RAM/no-swap conditions for Part 2 and temporary restore homes as well as Part 1. In the intended fresh FAT public-volume flow, the script's public-stick writes are limited to the three named files.
