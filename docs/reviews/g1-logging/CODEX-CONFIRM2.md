# G1 dispositions — findings

Review scope: commit `89e2b10` only, with surrounding source traced for its call paths. Classifications address items 1, 3, 4 and 6 of `CODEX-CONFIRM.md`; items 2 and 5 are accepted residuals, and signer logging is deferred as stated in the brief. Source review; no deployment or suite result is asserted.

1. **PARTIAL — note strings are filtered by syntax, not provenance.** `NOTE_TOKEN` accepts `SECRET`, `Bearer SECRET`, `example.com` and `exception secret` (`service/issuer/tessera_issue/service.py:32,72-73`); it cannot distinguish credentials, hostnames, exception text or content from literal tags. In the real calls, `what` is always built with `/` and therefore is withheld (`service/issuer/tessera_issue/pipeline.py:1275-1276`); direct exception objects are rendered as class names, not their text (`service/issuer/tessera_issue/service.py:65-69`). Other real calls pass dynamic strings including `before`, signer `slot`, and exception class names (`service/issuer/tessera_issue/pipeline.py:235,488`). For example, a configured signer slot named `SECRET` is emitted by the response-error call, and a dynamically named adapter exception class `SECRET` is emitted by the stage-error call. These require the secret to occupy those fields; the diff does not establish that normal request content or ordinary exception messages reach them. A complete URL containing `/` is rejected, but a hostname or other URL component can pass. The separate unvalidated API route/method issue in item 1 is untouched by this diff (`service/issuer/tessera_issue/lambda_app.py:73-74,84-85`).

3. **PARTIAL — the cited note exceptions are caught, but a new caller can raise after a commit.** `note` now catches a failing `__str__`, list append, rendering, or emission (`service/issuer/tessera_issue/service.py:57-79`). However, the new API import and argument evaluation occur outside `emit`'s guard (`service/issuer/tessera_issue/api.py:102-105`; `service/issuer/tessera_issue/logs.py:13-18`). For example, if the import raises `MemoryError` or `ImportError`, the upload-to-frames save has already succeeded but `_finish_upload` raises instead of returning the record. The added synchronous write can also block after that save; this is the accepted item 2 residual. No claim is made that `emit` itself propagates a stdout exception.

4. **PARTIAL — API transition is now emitted after successful save, subject to the disclosed delivery gap.** A successful upload-to-frames save reaches the new `request_stage` line, while a failed save skips it (`service/issuer/tessera_issue/api.py:100-106`). For example, process termination or stdout failure after the save still leaves a committed transition with no line; emission is best effort (`service/issuer/tessera_issue/logs.py:13-18`). The same new post-save import can abort the API response as described in item 3. The gap is part of the accepted item 5 residual, not proof that every committed transition produces a line.

6. **NOT FIXED — `TRAILING` remains a real signer reason that is remapped.** `Cursor.end` defaults to `TRAILING`, and `read_frame` calls it after reading a frame (`service/verifier/tessera_verify/codec.py:158,170-172`). Append a byte to a correctly framed manifest or attestation: both signer frame checks forward that `Fault.code` as a refusal (`service/signer-kms/tessera_sign_kms/signer.py:168-174`; `service/signer-gcp/tessera_signer/policy.py:106-114`). `TRAILING` is absent from the added allowlist, so the issuer maps it to `UNRECOGNIZED_REASON` and retains diagnostic bytes (`service/issuer/tessera_issue/pipeline.py:497-514`). The new drift test searches literal `Fault(...)` and `demand(...)` arguments but misses the default argument to `Cursor.end` (`service/issuer/tests/test_logging.py:256-263`). The added entries do preserve `TAG_UNKNOWN` and `TAG_MISMATCH`. Diagnostic storage and its possible failure on remapped responses remain as previously identified; adding `TRAILING` changes that path for this reason.
